## 修复「pimpleFoam 反复超时重跑」问题（16:40）
用户截图：`pimpleFoam 求解` 245s 失败 → 自动纠错 → 确定性补丁 → 再求解 → 再失败……循环 6 轮。

### 根因（算力预算 vs 物理时间需求）
- 算例 50e607（轴流压气机，MRF+叶片力源）被 LLM 写成 **pimpleFoam 瞬态**，`endTime=0.5, deltaT=5e-05`。
- 1500rpm → 一圈 0.04s，0.5s=12.5 圈，需 **10000 步**；但单核 9600 cell 网格 240s 只跑 ~1863 步（0.04s）。
- `run_case` 固定 `timeout 240` → 240s 跑不完 0.5s → 无 End → `converged_ok=False` 判「求解未到 endTime」→ LLM 自动纠错重写文件从头再跑 → 再 timeout → **6 轮空烧**。
- **本质矛盾**：MRF + fvOptions 叶片力源是「定常等效模型」，物理上就没有非定常结构，用瞬态 pimpleFoam 跑 12 圈毫无意义，纯烧算力。

### 修复（foam_agent/app.py）
1. **`force_steady_for_actuator_case(case_dir)`**：检测到「MRFProperties + fvOptions(vectorSemiImplicitSource) + 瞬态求解器」三条件齐备 → 强制改 `simpleFoam`，`endTime=1000 / deltaT=1 / writeInterval=100`，并同步重写 fvSchemes/fvSolution 为稳态 SIMPLE。幂等（已稳态不重复改），无 fvOptions 的普通算例不碰。
2. **`patch_transient_time_budget(case_dir, solver, timeout_s)`**：非等效模型的纯瞬态算例（真实叶片/滑移网格），按 `网格 cell 数 × 240s × 效率系数` 估算可完成步数，把 `endTime` 收缩到预算内（≥2 转子周期），并同步收缩 `writeInterval`。
3. **`run_case` 判定放宽**：新增 `budget_ok`——**无 FATAL 且已推进出有效时间即视为「预算内正常完成」**，不再判失败、不再触发 LLM 纠错重跑（消除无限重跑根因）。
4. `run_case` 里先以 `controlDict` 的 `application` 为准更新 `solver`（避免补丁改了 application 却还用旧 solver 名跑）。

### 验证（全部通过）
- 回归测试 temp/test_transient_fix.py（5/5 PASS）：强制稳态、幂等、瞬态收缩、稳态不碰、无 fvOptions 不碰。
- **实测**：把 50e607 副本强制稳态后实跑 `simpleFoam` → **32.26s 跑满 1000 步 `End`，0 FATAL**，残差 Ux 1.47e-05 / p 4.05e-05 收敛。对比修复前 pimpleFoam 需 ~1444s 且必超时。
- 重启 8502 服务（新代码）：PID 37280，HTTP 200，进程环境含 DEEPSEEK_V3_KEY(116)，LLM 端到端 `status: done` 无错。

### 关键经验
- **MRF+叶片力源等效模型必须用稳态 simpleFoam**，瞬态 pimpleFoam 只是空烧算力；要捕捉真实动静干涉需上滑移网格（sliding mesh），但那是另一个量级的构建成本。
- `run_case` 固定 240s 超时时，必须让「endTime ≤ 预算」或「无 FATAL 有进展即算成功」，否则必然无限重跑。
